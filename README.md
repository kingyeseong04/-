# Bybit-style Replay — 과거 캔들 실시간 매매 연출

**바이비트(Bybit) 거래소 UI를 그대로 재현**한 화면 위에서, **과거 캔들 데이터**를 틱 단위로 실시간처럼 재생하는 도구입니다. 과거 시점을 골라 그 순간 실시간으로 트레이딩하는 것처럼 **연출(영상용)**하는 것이 목적입니다. 캔들이 자라나는 동안 **롱/숏 포지션을 잡고, 틱마다 미실현 손익·포지션·청산가·잔고가 실시간으로 갱신**됩니다.

바이비트 UI 요소: 상단 시세바(Mark·24H High/Low·펀딩 카운트다운), **미실현 손익·Equity·Available 패널**(원화 환산 포함), 레버리지 칩, 초록 Buy/Long·빨강 Sell/Short 버튼, **TP/SL 자동 청산**, 하단 Positions/Trade History 탭. 차트는 바이비트가 실제로 쓰는 것과 같은 TradingView(lightweight-charts)로 그립니다.

> 차트 라이브러리(lightweight-charts)는 `js/vendor/`에 포함되어 있어 **오프라인/네트워크 차단 환경에서도** 동작합니다.

### TradingView와 정확히 맞추기

- **거래소 = Bybit 무기한(.P)**: 데이터는 Bybit v5에서 받아옵니다. (브라우저에서 Bybit이 막힌 환경에서는 자동으로 바이낸스 `fapi` 무기한으로 폴백하고, 상태바에 `⚠ → Binance`로 알립니다.)
- **로컬 시간축**: 차트 시간축·크로스헤어를 보는 사람의 **로컬 타임존(예: KST)**으로 표시해, TradingView(로컬 시간 표시)와 캔들이 정렬됩니다. (UTC로 그리면 9시간 어긋나 다른 캔들처럼 보임)
- **실제 캔들 내부 움직임**: 재생 구간의 **더 낮은 타임프레임(5m→1m, 1h→1m, 4h→5m, 1d→15m)** 실제 캔들을 받아와 캔들 내부를 채웁니다. 즉 재생 중 오르락내리락이 **실제 시장 틱에 근접**합니다(상태바에 `real ticks ✓`). 서브 데이터를 받지 못한 경우에만 합성 틱으로 폴백합니다.
- Bybit이 브라우저에서 막힌 환경(CORS·지역 차단)에서는 자동으로 바이낸스로 폴백하고, 상태바에 `⚠ ... → Binance`로 알립니다.

## 핵심 아이디어

캔들은 OHLC(시가/고가/저가/종가)만 저장하므로 캔들 내부의 실제 체결 순서는 알 수 없습니다. 이 도구는 다음 조건을 만족하는 **그럴듯한 틱 경로를 합성**합니다.

- 시가에서 시작해 종가로 정확히 끝남
- 고가와 저가를 반드시 한 번씩 찍음
- `[저가, 고가]` 범위를 절대 벗어나지 않음
- 캔들 내부에 여러 개의 웨이포인트를 두어 **여러 번 오르락내리락(반전)** 하고, 그 사이는 브라운 브리지(Brownian bridge)로 자연스럽게 흔들림 → 포지션 손익도 캔들 동안 실시간으로 출렁임 (예: 60틱 5분봉이면 캔들당 ~30회 방향 반전)

`js/tickEngine.js`에 구현돼 있습니다.

## 실행 방법

별도 빌드가 필요 없는 순수 정적 웹앱입니다. 로컬 서버로 열면 됩니다.

```bash
# 아무거나 하나
python3 -m http.server 8000
# 또는
npx serve .
```

브라우저에서 `http://localhost:8000` 접속.

## 데이터 불러오기

화면 하단에서 **심볼 · 시간봉(`15m·1h·4h·1d`) · 시작 날짜·시각 · 앞뒤 캔들 개수**를 정하고 **Load**를 누릅니다. 심볼은 전부 **Bybit 무기한 선물**이라 모두 실제 틱을 지원합니다: `BTCUSDT.P · ETHUSDT.P · SOXLUSDT.P · TSLAUSDT.P · COHRUSDT.P · ALABUSDT.P · DRAMUSDT.P · XAUUSDT.P · SAMSUNGUSDT.P`. TradingView식 `.P`는 자동으로 제거해 Bybit 무기한으로 조회합니다. 지정한 날짜를 중심으로 **앞/뒤 캔들 개수(각 최대 1000, 기본 100)** 만큼 **Bybit v5** 공개 API에서 받아옵니다. (거래량은 표시하지 않고 캔들만 그립니다.)

- **날짜는 필수**입니다 — 과거 특정 시점에서 실시간처럼 재생하는 게 목적이라 항상 날짜 기준으로 동작합니다.
- **폴백 사슬**: Bybit이 브라우저에서 막히면(CORS·지역 차단) → 바이낸스 무기한(`fapi`) → 바이낸스 현물(`api`, CORS가 확실한 최후 수단) 순으로 자동 시도합니다. 실제로 데이터를 준 곳이 화면에 표기됩니다.
- 셋 다 실패하면 차트 가운데에 **에러 메시지**가 크게 표시됩니다(원인 포함).
- (브라우저에서 거래소 API를 직접 호출하므로 네트워크 접근이 필요합니다.)

## 영상용 프레임 모드 (`🎬 프레임`)

바이비트 포지션 탭을 그대로 옮긴 **상단 띠 + 캔들만 있는 차트**입니다.

- 상단 띠는 바이비트 Positions 행과 동일한 세 칸: **Contracts**(심볼 + `Perp` 칩 + `Cross N.NNx`, 왼쪽에 사이드색 세로 바) · **Qty**(기초자산 단위, 예 `15.668 BTC`) · **Unrealized P&L(ROI)**(USDT · `(ROI%)` · `≈₩`). 바이비트는 `≈` 뒤에 USD를 쓰지만 여기서는 **로드한 날짜 기준 환율로 환산한 원화**를 씁니다.
- 롱이면 초록, 숏이면 빨강으로 세로 바·레버리지·수량이 함께 바뀌고, 손실이면 P&L 세 줄이 빨강이 됩니다.
- 좌상단 OHLC 범례는 숨깁니다 — 같은 숫자가 위 띠에 있습니다.
- 차트는 고정 비율 상자를 쓰지 않고 **하단 플로팅 도구 바로 위까지** 세로를 다 씁니다.

## 영상 녹화용 클린 모드

차트를 영상 소스로 쓸 수 있도록, **차트만 전체화면으로** 보여주는 클린 모드가 있습니다.

- 하단 **`⛶ Clean`** 버튼 또는 **`F`** 키 → 트레이딩 패널·컨트롤바를 모두 숨기고 차트만 화면을 꽉 채웁니다(가능하면 브라우저 전체화면도 함께). **`Esc`** 로 빠져나옵니다.
- 창 크기에 맞춰 **반응형**이라, 녹화할 창을 16:9(가로)나 9:16(세로)로 맞추면 그 비율대로 차트가 채워집니다.

차트는 트레이딩뷰와 동일하게 보이도록 다음 요소를 포함합니다.

- 배경 **심볼 워터마크**(예: `BTCUSDT · 1h`)
- **좌상단 OHLC 범례** — 심볼·인터벌·거래소 + O/H/L/C 값과 등락률(상승/하락 색)
- **현재가 점선 라인 + 가격축 라벨**(캔들 방향 색)
- 트레이딩뷰 최신 기본 캔들색(상승 `#089981` / 하락 `#f23645`), Trebuchet MS 폰트, 동일한 그리드·크로스헤어 톤

## 조작법

- **Play / Pause** — 재생/일시정지 (단축키 `Space`)
- **Restart** — 같은 데이터로 처음부터 다시
- **배속(Speed)** — **실시간 대비 배속**입니다. `1×`면 1봉이 실제 봉 길이만큼(예: 1분봉=60초), 배속을 올릴수록 빨라집니다(최대 3600×). 라벨에 **현재 시간봉 기준 1봉이 몇 초/분에 만들어지는지**(`N× · 1봉≈X초`) 자동 표시됩니다.
- **레버리지** — `1×`~`125×` (주문 패널 슬라이더).
- **시작 자본 (USDT)** — 주문 패널에서 시작 잔고를 직접 정합니다.
- **재생 중에는 시작 자본·배속·틱 설정이 잠깁니다** — 값을 바꾸려면 일시정지(Space) 후 변경하고 다시 재생하세요.
- **배속 직접 입력** — 슬라이더 옆 숫자칸에 배속을 직접 입력(1~3600). 슬라이더와 자동 동기화.
- **🔒 고정** — 현재 생성 중인 봉에 차트를 고정(기본 On). 마우스로 차트가 움직이지 않아 녹화에 좋습니다. 끄면 자유롭게 이동/확대.
- **💰 손익** — 미실현 손익을 차트 위에 크게 표시(영상용). 드래그로 위치 이동.
- **💵 잔고** — 지갑 잔고(Wallet Balance)를 크게 표시. 드래그로 위치 이동.
- **TP / SL** — 주문 패널에서 익절가(TP)·손절가(SL)를 입력하면 차트에 라인이 표시되고, 재생 중 가격이 도달하면 **자동 청산**됩니다.
- **환율 (₩/USDT)** — 주문 패널에서 환율을 직접 입력하면, 손익·잔고 오버레이와 패널에 **한화(₩) 환산액이 자동 표시**됩니다.
- **📈 지표** — 지표 On/Off + 설정:
  - **볼린저밴드**: 기간(기본 20)·승수(기본 2)
  - **일목균형표**: 전환(9)·기준(26)·선행B(52)·선행이동(26). 구름(선행스팬 A/B 사이)까지 채워지고 미래로 투영됩니다.
  - 둘 다 **OHLC만으로 계산(거래량 불필요)**. 날짜 로드 시 지표 계산용 이력(앞 130봉)을 함께 받아와 로드 직후 바로 표시됩니다.
- **순서** — `① 심볼·시간봉·날짜 선택 → ② Load → ③ Play`. 데이터를 불러오기 전에는 Play/Restart가 비활성화되고, 재생 중에는 시작 자본·배속이 잠깁니다(일시정지 후 변경).
- **시간봉 자유 전환** — 같은 심볼일 때:
  - **날짜를 그대로 두고 시간봉만 바꿔 Load** → **현재 재생 시점에서, 포지션·잔고·레버리지 그대로 이어서** 재생 (`포지션·잔고 유지 (이어서)`). 5분봉이 너무 짧으면 1시간봉으로 갈아타 계속 진행하는 식.
  - **날짜를 바꿔 Load** → 그 새 시점으로 이동. 잔고·레버리지는 유지하되 열려 있던 포지션은 현재가로 정산됩니다.
  - **심볼 변경 / Restart** → 시작 자본으로 초기화.
- **✏️ 선 / 📏 자 / 🧲 마그넷** — 차트 위 드로잉 도구:
  - **선**: 드래그로 추세선을 그림(여러 개 유지). 캔버스 **더블클릭 = 전체 삭제**.
  - **자**: 드래그한 구간을 바이비트식 측정 상자로 표시 — **상승=파랑 / 하락=빨강**, `가격차 (%) 틱수 / N bars, 시간`.
  - **마그넷**: 켜면 그리는 점이 가장 가까운 캔들의 **O/H/L/C 값에 스냅**됩니다.
  - 클린 모드에서도 좌하단 플로팅 툴바로 사용할 수 있습니다.
- **진입가 지정** — 주문 패널의 "진입가 지정" 칸에 값을 넣으면 **그 가격에 진입**합니다(비우면 현재가). 예: 현재가 120인데 100에 롱을 누르면 즉시 +20% 상태로 잡힙니다(연출용).
- **자동 환율** — 로드 시 지정한 **날짜 기준 USD/KRW 환율**(ECB/frankfurter → 실패 시 Yahoo `KRW=X`)을 자동으로 받아 채우고, 환율칸 옆에 그날 환율·출처를 작게 표시합니다. 직접 수정도 가능.
- **Long (L) / Short (S)** — 진입가 지정 시 그 가격, 아니면 현재 틱 가격으로 진입
- **Close All (C) / Close 50%** — 청산

`Margin`(증거금)과 `Leverage`(레버리지)로 포지션 크기를 정합니다. (명목 = 증거금 × 레버리지)

## 매매 모델 (`js/trading.js`)

- 순포지션(netting) 방식: 같은 방향이면 평단 가중평균, 반대 방향이면 부분/전체 청산 후 남으면 반대로 플립
- 미실현/실현 손익, 자산(equity), 가용 증거금 실시간 계산
- 테이커 수수료 0.04% 반영
- 고립 증거금 가정의 추정 청산가 계산 (차트에는 진입가 라인만 표시, 청산가 라인은 표시하지 않음)
- 자산이 유지증거금 아래로 떨어지면 자동 청산
- 차트 위 포지션 라벨은 바이비트와 동일: `[P&L ±값(어두운 박스·흰 글씨)] [사이즈(사이드색 채움)] [⇅ 반전] [✕ 청산]`, 전체를 사이드색(롱 초록/숏 빨강) 테두리로 감쌈. `⇅`는 포지션을 반대 방향·동일 수량으로 반전.

## 네온 선 연출 도구 (`paint.html`)

차트 **캡처 이미지 위에 점을 찍어** 지지·저항선이나 돌파 화살표를 그리고, 그 선이 **네온으로 그려지는 애니메이션**을 영상으로 뽑는 별도 페이지입니다. 같은 사이트의 `/paint.html` 경로로 열립니다. 거래소 API를 쓰지 않아 **네트워크 없이** 동작하고, 올린 이미지는 브라우저 밖으로 나가지 않습니다.

- **세로 화면 우선**: 아이패드를 세로로 들고 쓰는 것을 기준으로 맞춰져 있습니다. 도구·색·획끝·되돌리기·배경·재생만 아래 두 줄에 남기고, 한 세션에 한두 번 건드리는 것들(이미지·비율·굵기·글로우·속도·획 간 대기·가감속·녹화)은 `⚙` 서랍으로 접었습니다 — 다 펼쳐두면 도구모음이 세로 화면의 **25%**(mini는 31%)를 먹고 캔버스가 그만큼 작아집니다. 접은 상태에서는 9%입니다. 누른 채 끌면 크기를 보면서 도형·선을 한 번에 그리고, **두 손가락**으로 배경 사진을 옮기거나 확대합니다. 버튼·색·슬라이더는 손가락 크기(44px)로 커집니다. 단축키는 키보드가 있을 때만 쓰는 보조 수단입니다.
- **도구 5종** (`Q` 선 · `W` 정원 · `E` 타원 · `R` 네모 · `T` 화살표)
  - **선**: 클릭한 순서대로 이어지는 직선(곡선 없음). `Shift`로 수평·수직·45° 고정, 수평에서 몇 px 이내면 자동으로 평평하게 맞춰집니다. **화살표**를 켜면 화살촉이 처음부터 펜 끝에 붙어 목표로 날아갑니다.
  - **도형**: 두 번 클릭해 대각선 양 끝을 잡으면 완성됩니다. **정원**은 어떻게 끌든 항상 완전한 원, **타원**은 가로세로 자유(`Shift`면 정원). 네모도 `Shift`면 정사각형. 다음 클릭 위치는 점선으로 미리 보입니다.
  - **화살표**: 미리 그려둔 네온 화살표 5개(빨·노·초·파·분)를 얹습니다. **꼬리 → 머리 방향으로 한 번 끌면** 그 길이가 크기, 그 방향이 각도가 됩니다 — 도형과 같은 두 점짜리 조작이고, 점을 다시 끌어 크기·각도를 고칠 수 있습니다. 색 선택이 곧 화살표 선택이며, 직접 지정한 색은 가장 가까운 5색으로 붙습니다. 끄는 동안에는 화살표 자체가 반투명하게 미리 보입니다.
- 도형도 선과 **똑같이 네온으로 그려지는 애니메이션**이 붙습니다. 내부적으로 원·네모를 촘촘한 폴리라인으로 펼쳐 선과 같은 경로를 타기 때문에, 이징·베이크·녹화가 전부 같은 코드로 동작합니다. 원은 12시에서 시계방향으로 그려집니다.
- **네온 렌더링**: 획을 작은 오프스크린 버퍼 2장(1/18 · 1/5 축소)에 그린 뒤 확대해 합성합니다 — 확대할 때의 이중선형 보간이 곧 블러라서, 굵기를 단계별로 겹치는 방식에서 보이던 **계단이 사라지고 감쇠가 연속적**입니다. 그 위에 색상 몸통과 살짝 밝힌 심지를 얹습니다(순백이 아니라 색조를 유지해야 유리관처럼 보입니다). `shadowBlur`로 큰 헤일로를 만들면 프레임이 밀려 녹화가 깨지므로 쓰지 않고, 블룸은 **획의 바운딩 박스 범위에만** 합성해 낭비를 줄입니다.
- **재생**: 획이 순서대로 그려집니다. 긴 선일수록 오래 걸리고, **획 간 대기**로 나레이션에 맞춰 뜸을 들일 수 있습니다.
- **펜 속도는 일정합니다(linear).** 가감속 곡선을 고를 수 있었지만 실제로 쓰이지 않아 걷어냈습니다 — 진행도는 이제 시간에 그대로 비례합니다.
- **색상**: 빨·노·초·파·분 고정 5색(`1`~`5`) + 직접 지정(브라우저 기본 색상 선택기, 폰에서는 OS 선택기). 옆의 HEX 칸에 `#FF2D95` 같은 코드를 바로 붙여넣을 수 있습니다.
- **배경 3종**: `사진` · `검정` · `흰색`. **검정**으로 녹화한 뒤 편집 프로그램에서 **스크린(Screen) 블렌드**로 얹으면 검정이 사라지고 네온만 남습니다. **흰색**에서는 가산 합성이 전부 하얗게 날아가므로, 네온을 halo + 색상 심지 방식으로 바꿔 그립니다.
- **녹화**: `⏺ 녹화` → 재생을 캡처해 자동 저장. 포맷은 **H.264 mp4를 우선**으로 고르고, 안 되면 webm으로 떨어집니다.
  - **60fps**가 기본입니다(`⚙` 안에서 30fps로 내릴 수 있음). 렌더 루프가 `requestAnimationFrame` 기반이라 화면 주사율만큼 프레임이 나오고, 캡처 트랙에 60을 요청해야 그것이 실제로 60fps 파일이 됩니다. 비트레이트도 같이 올립니다(60fps 26Mbps / 30fps 16Mbps) — 프레임 수가 두 배가 되면 같은 비트레이트에서 네온 그라데이션에 띠가 집니다.
  - 요청한 프레임레이트가 곧 결과는 아니므로, 녹화가 끝나면 **그 기기가 실제로 뽑아낸 프레임레이트**를 녹화 버튼 옆에 표시합니다(`실측 60fps / 요청 60fps ✓`). 많이 못 미치면 굵기·글로우를 낮추거나 30fps로 내리라고 알려줍니다.
  - iOS는 webm을 **재생하지 못합니다.** 그래서 mp4를 먼저 시도합니다.
  - 다만 `video/mp4`를 코덱 없이 요청하면 크로미움은 **VP9를 mp4 껍데기에 담아** 줍니다(ftyp 브랜드가 `isom/iso6/iso2/vp09`, `avcC` 박스 없음). 확장자만 mp4일 뿐 iOS에서는 똑같이 안 열립니다. 그래서 **H.264를 명시적으로 지원할 때만** mp4를 쓰고, 아니면 정직하게 webm으로 저장합니다.
  - 파일 확장자는 요청한 포맷이 아니라 `recorder.mimeType`(실제 협상된 결과)을 보고 정합니다.
  - **파일명**을 녹화 전에 미리 정할 수 있습니다(`⚙` 안). 비우면 `neon-(시각)`. iOS에는 저장 위치를 고르는 대화상자가 없고(File System Access API는 크롬 데스크톱 전용) 다운로드 이름은 `<a download>`이 정하므로, 이름은 앱 안에서 정하는 수밖에 없습니다.
  - **녹화 첫 프레임이 빈 화면입니다.** `captureStream`은 붙는 순간의 캔버스를 그대로 가져가는데 거기엔 편집 중이던 완성 그림이 남아 있어서, 예전에는 1번 프레임이 완성본으로 찍혔습니다. 지금은 스트림을 붙이기 전에 t=0 프레임을 먼저 그립니다.
- **전체화면은 시작 프레임을 보여줍니다.** 캡처용 화면이니 편집하던 완성본이 아니라 애니메이션이 시작될 상태를 띄웁니다 — 화면녹화를 켜고 `▶ 재생`만 누르면 됩니다. 재생이 끝나면 완성 상태로 남습니다.
- 화면 녹화를 쓸 수도 있습니다 — 전체화면에서 재생을 누르면 화면 위 버튼이 **그 즉시 사라져** 녹화에 찍히지 않습니다.
- 비율은 `3:4`(기본) · `9:16` · `1:1` · `4:5` · `16:9`. 점은 정규화 좌표로 저장돼 비율을 바꿔도 상대 위치가 유지됩니다.
- **선명도**: 좌표는 논리 좌표(예: 1080×1440)로 두되, 캔버스 실제 픽셀은 **화면에 표시되는 기기 픽셀과 1:1**로 맞춥니다. 브라우저가 캔버스를 늘리거나 줄이는 순간 사선·곡선이 계단처럼 깨지기 때문입니다(가로세로 반듯한 선은 멀쩡해서 눈치채기 어렵습니다). 녹화 중에는 표시 크기와 무관하게 최소 논리 해상도로 올려 잡습니다.
- 도구모음 오른쪽에 **빌드 번호**가 표시됩니다. 배포된 최신 버전을 보고 있는지 확인하는 용도이고, `css`/`js`도 `?v=` 쿼리로 요청해 브라우저 캐시가 옛 코드를 붙들지 않게 합니다.
- **전체화면**: 우하단 `⛶` 또는 `F`. 아래 가운데 **`▶ 재생`**, 나갈 때는 **우상단 `✕` 버튼**이나 `Esc` — `✕` 버튼은 몇 초 뒤 흐려지지만 사라지지는 않아, 키보드가 없는 화면에서도 항상 빠져나올 수 있습니다.
- 조작법 전체는 페이지 우하단 `?` 버튼에 있습니다.

> 캔버스 녹화는 브라우저가 지원하는 포맷을 자동으로 고릅니다(Chrome VP9 webm / 사파리 H.264 mp4). 인코딩된 프레임이 하나도 없으면 빈 파일을 내려주지 않고 안내합니다.

> 유휴 상태에서는 캔버스를 다시 그리지 않습니다(태블릿 발열·배터리). 재생·녹화 중이거나 무언가 바뀐 프레임에서만 그리고, 유휴 프레임에서는 스케줄 계산조차 하지 않습니다.

> 렌더 루프에서 매 프레임 다시 만들던 **배경 + 완성된 획**은 한 장(plate)으로 미리 합쳐 두고 그것만 얹습니다. 애니메이션 중 프레임마다 달라지는 건 그리는 중인 획 하나뿐이라, 배경 사진과 베이크를 초당 60번 다시 합성할 이유가 없습니다 — 전체 캔버스 연산 4개가 1개로 줄어 소프트웨어 렌더 기준 **+31%**였습니다. 블룸 확대는 `imageSmoothingQuality`를 `low`(이중선형)로 둡니다. 원본이 이미 흐릿한 축소본이라 고품질 리샘플링이 복원할 게 없어 **눈으로 같은 그림**인데(채널당 평균 차이 1 미만) 비용은 약 4배입니다.

> 그 밖의 최적화: 획 길이를 캐시해 스케줄러가 매 프레임 모든 점을 다시 훑지 않게 했고(원 하나가 최대 320점), 상태 표시줄 문자열은 값이 바뀔 때만 DOM에 씁니다. 포인터 좌표 변환은 캔버스 사각형을 캐시해 드래그 중 매 프레임 레이아웃을 강제하지 않습니다. 녹화가 끝나면 캡처 트랙을 명시적으로 정지해 컴포지터가 계속 프레임을 뽑지 않게 합니다.

## 빗각 알림 (`angle.html`)

인범TV식 **빗각(피보나치 채널)** 을 종목별로 쌓아두고, **주가가 그 선에 닿으면 알려 주는** 별도 페이지입니다. 같은 사이트의 `/angle.html` 경로로 열립니다.

작도 → 저장 → 감시가 한 화면에서 끝납니다.

- **세 번 탭으로 작도**: 오른쪽 `빗각` 버튼을 켜고 ① 추세선 시작 → ② 추세선 끝(= 0선) → ③ 1:1 선이 지날 점을 탭하면 끝입니다. 트레이딩뷰 피보나치 채널의 1·2·3번 점과 **같은 정의**라 화면에 나오는 선도 같습니다. `자석`을 켜두면 근처 캔들의 시·고·저·종에 점이 붙습니다.
- **레벨**: `0, 0.5, 1, 1.5, 2, 2.5, 3` 이 기본입니다. `1`이 1:1, `1.5`가 1:1.5, `2`가 1:2입니다. 빗각마다 자유롭게 고칠 수 있고(`0.618` 같은 값도 됩니다), 정수는 파랑·반값은 노랑으로 트레이딩뷰와 같게 그립니다.
- **수식**: 1·2번 점이 기준선(레벨 0), 3번 점이 채널 폭을 정합니다.
  `d = p3 − base(x3)`, `레벨 L 선 = base(x) + L × d`. `base`는 x에 대한 1차 함수라 레벨 간격이 항상 일정합니다.
  x축은 **시간이 아니라 봉 인덱스**입니다 — 트레이딩뷰가 그렇게 그리기 때문에 휴장 공백이 있는 종목에서도 선이 어긋나지 않습니다(24시간 도는 무기한 선물이면 둘이 같은 값이라 결과가 동일합니다).
- **감시**: `감시 시작`을 누르면 저장된 빗각들의 심볼·시간봉별로 최신 캔들을 주기적으로(기본 20초) 받아, 그 봉의 **고가·저가가 선을 통과했는지**로 터치를 판정합니다. 종가만 보지 않기 때문에 **꼬리로 스친 터치도 잡습니다.** 허용오차(기본 0.1%)만큼 여유를 둡니다.
- 같은 봉·같은 레벨에서는 **한 번만** 울립니다. `근접 알림`을 켜면 터치 전에 미리(기본 0.5% 이내) 한 번 더 알려 줍니다.
- 알림은 **브라우저 알림 + 소리 + 화면 표시** 세 가지로 나갑니다. 목록 카드에는 항상 *가장 가까운 선과 거리(%)* 가 표시돼, 알림이 오기 전에도 어디쯤 왔는지 보입니다.
- **좌표로 추가**: 이미 트레이딩뷰에 그려둔 빗각은 도형을 길게 눌러 **설정 → 좌표**를 열면 1·2·3번 점의 시간·가격이 그대로 나옵니다. 그 숫자를 넣으면 똑같은 선이 재현됩니다.
- **저장**은 브라우저(localStorage)입니다. 종목별로 묶여 목록에 쌓이고, `내보내기`/`불러오기`로 폰↔PC를 오갑니다.

### 알림이 실제로 오는 범위 (중요)

이 페이지의 알림은 **페이지가 열려 있는 동안**만 동작합니다. 브라우저 탭이 백그라운드로 내려가면 타이머가 느려지고, 탭을 닫으면 감시도 멈춥니다. 아이폰은 사파리에서 **홈 화면에 추가**한 뒤 열어야 브라우저 알림이 뜹니다.

**폰이 잠겨 있어도 오는 진짜 푸시**가 필요하면, 각 빗각의 `Pine` 버튼으로 스크립트를 복사해 트레이딩뷰 Pine 에디터에 붙여넣고 알림(Alert)을 거세요. 앵커 세 점과 레벨·허용오차가 그대로 박힌 스크립트가 나옵니다 — 조건에서 `Any alert() function call`을 고르면 터치할 때마다 트레이딩뷰 앱 푸시가 옵니다. (Pine 쪽은 시간 기준이라 24시간 거래 종목에서 정확하고, 장 마감이 있는 종목은 휴장 구간만큼 기울기가 미세하게 다를 수 있습니다.)

> 데이터는 메인 앱과 같은 로더를 씁니다 — Bybit v5 → 바이낸스 무기한 → 바이낸스 현물 순으로 폴백합니다. 어디서 받았는지는 차트 왼쪽 위에 표시됩니다.
